# ОБҲУШ · Water Intelligence

Рабочая платформа анализа водных ресурсов для выбранного участка системы Вахша / Нурека. Интерфейс на русском и таджикском. Данные погоды и модельного речного стока загружаются из Open-Meteo; 3D-рельеф подготовлен из реальных AWS Terrain Tiles.

## Запуск

Нужен **Node.js 24+**. Все команды выполняются из корня этого репозитория.

```bash
npm ci --cache /tmp/obhush-npm-cache
npm run build
npm start
```

Сервер слушает порт **3000**, который можно изменить переменной `PORT`. Для разработки с автоматическим перезапуском: `npm run dev`.

В поставке уже есть реальные сохранённые данные и рельеф. Для обновления погоды и стока:

```bash
npm run data:refresh
```

Кнопка «Обновить данные» делает то же через сервер, сохраняя новый набор в `data/runtime/snapshot.json`. При недоступности источников старый набор не перезаписывается. Полученные даты видны в интерфейсе. Набор старше 24 часов отмечается предупреждением.

После установки зависимости, шрифт, карта и сохранённые данные доступны без внешнего интернета. **Локальный сервер должен продолжать работать.** Обновление внешних данных и ответы удалённой языковой модели требуют подключения.

## Что работает

- Интерактивный 3D-рельеф: вращение, масштаб, плоский вид, точки объектов и разворачивание карты. 30 720 реальных высот, вертикальное преувеличение 1,65.
- Погода для Нурека, Рашта и верховьев: средняя температура, осадки и снег. Координаты/высота ячейки доступны в источниках.
- 180 предыдущих дней, текущий день и 7 будущих дней модельного стока GloFAS, если доступны у поставщика.
- Локальная ML-модель Ridge для изменения стока, независимая хронологическая проверка и сравнение с базовым прогнозом.
- Ежедневный водный баланс: приток, выпуск, испарение, перелив и конечный запас.
- Расчёт энергии с напором, КПД и ограничением расхода турбин; покрытие заданной потребности в поливе.
- Перебор 81 режима выпуска с ограничениями по резерву и покрытию потребности в поливе.
- CSV-импорт пользовательских измерений; последний запас можно применить к сценарию. Данные импорта хранятся только в этом браузере.
- Экспорт результатов CSV и автономного HTML-отчёта. Откройте HTML и используйте кнопку PDF / Print для PDF.
- Помощник, объясняющий текущие расчёты. Без ключа работает явно обозначенный локальный аналитический модуль; с ключом — языковая модель.
- Встроенная презентация на 5 экранов: стрелки клавиатуры, Escape для выхода.
- Адаптивный интерфейс для телефона.

## ИИ-помощник

Создайте `.env` на основе `.env.example` или задайте переменные в настройках среды. **Ключи не коммитить и не передавать в браузер.**

```dotenv
LLM_API_KEY=your-openrouter-key
LLM_MODEL=openrouter/free
PORT=3000
```

Используются только `openrouter/free` или модели с суффиксом `:free`; платная модель автоматически заменяется бесплатным маршрутизатором. При лимите или недоступности провайдера ответ даёт явно обозначенный локальный расчётный модуль.

После подключения ключа перезапустите сервер. Проверка `/api/health` сообщает только наличие ключа, не его значение. Фактическая работа провайдера проверяется вопросом помощнику. Провайдеру отправляются вопрос и числовой контекст выбранного сценария. Исходный импортированный CSV целиком не отправляется. Контекст может включать применённый пользователем начальный запас.

## Источники и научные ограничения

| Данные | Источник | Смысл |
|---|---|---|
| Сток | [Open-Meteo Flood API / GloFAS](https://open-meteo.com/en/docs/flood-api) | Модельный сток в ячейке, не фактический гидропост |
| Погода | [Open-Meteo Weather](https://open-meteo.com/en/docs) | Данные трёх отдельных точек, не среднее по маске бассейна |
| Высоты | [AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) / Mapzen | Сохранённые высоты; [атрибуция исходных наборов](https://github.com/tilezen/joerd/blob/master/docs/attribution.md) |
| Линия реки | Схематическая соединительная линия | Ориентир, не точная геометрия русла или граница водосбора |
| Объекты | Координаты ориентиров | Не телеметрия станции |
| Запас и параметры ГЭС | Изменяемые параметры пользователя | Не подтверждённый паспорт или фактический текущий уровень |

Open-Meteo требует атрибуции согласно опубликованным условиям (в частности CC BY 4.0 для API-данных); при коммерческом использовании проверьте актуальный тариф и лицензию поставщика. Локальный шрифт Manrope распространяется по SIL OFL; текст лицензии в `public/fonts/OFL.txt`.

Модельный баланс в млн м³:

```text
V(t+1) = V(t) + Q_in × 0.0864 − Q_out × 0.0864 − evaporation − spill
E_day [ГВт·ч] = 1000 × 9.81 × min(Q_out, turbineLimit) × H × efficiency × 24 / 1e9
```

Выпуск проходит турбины и затем может использоваться для орошения ниже по течению. Полив не вычитается из запаса второй раз. Канальные потери, задержки, меняющийся напор, другие водопользователи, каскад ГЭС и правила диспетчеризации не моделируются. Значение покрытия полива относится только к введённой потребности у выхода рассматриваемой модели.

Оптимизатор перебирает выпуск 0–2000 м³/с с шагом 25. Допускаются режимы, сохраняющие пользовательский резерв каждый день и среднее покрытие полива ≥95%. Цель: 0,55 × нормированная энергия + 0,45 × доля конечного запаса. Это прозрачное сравнение сценариев, не рекомендация оператору реальной ГЭС.

**ML:** прогнозируется суточное изменение модельного стока. Признаки — изменения за последние 1/2 дня, среднее изменение за 7 дней и годовые sine/cosine. Ridge-штраф выбирается среди 0,2/2/20/200 на двух ранних временных срезах обучающей части. Последние 14 исторических дней исключены из подбора и обучения проверяемой модели. Проверка однодневная, с фактически известными предыдущими значениями модельного ряда. Для будущих 7 дней модель переобучается на доступной истории и работает рекурсивно. Недельная ошибка отдельно не подтверждена. Источник основного притока сценария — прогноз GloFAS; локальная модель используется как явно различимый альтернативный прогноз и резерв при отсутствии данных GloFAS.

Не реализованы: сегментация актуальных спутниковых снимков снега, оценка объёма воды в леднике, официальная телеметрия водохранилища, калиброванная гидрологическая модель всего водосбора, предупреждения о паводках, прогноз отключений и урожайности. Эти возможности требуют дополнительных данных и проверки, их нельзя заявлять на защите как готовые.

## Проверки

```bash
npm run build
npm test
# В другом терминале уже должен работать сервер на порту 3000:
npm run test:e2e
```

Браузерные проверки используют Chromium из `/usr/bin/chromium`. Для другой установки задайте `CHROMIUM_PATH` или адаптируйте конфигурацию Playwright. Проверяются сценарии, карта, настройки, импорт, экспорт, помощник, презентация, RU/TJ, мобильная ширина и валидация API.

## Структура

```text
src/                 React, интерфейс и 3D-карта
shared/model.ts      водный баланс и поиск режима
shared/forecast.ts   ML и проверка прогноза
server/              Express API, загрузка данных, помощник
data/snapshot.json   сохранённый реальный набор
public/terrain.json  сохранённая сетка высот
scripts/             обновление данных и построение рельефа
docs/DEFENSE.md      сценарий выступления
tests/               расчётные и браузерные проверки
```

Для повторного построения рельефа нужен Python с Pillow: `python scripts/prepare-terrain.py`. Для обычного запуска это не требуется.

## Контейнер и передача проекта

Подготовлены `Dockerfile` и `deploy/compose.yml` для отдельного процесса с лимитами ресурсов. Образ нужно собирать вне действующего клиентского VPS. В Compose нет сборки; по умолчанию доступ открыт только через loopback-порт 43100. Секрет передаётся отдельным `runtime.env`, не включается в образ. Подробности: `docs/DEPLOYMENT.md`.

`python3 scripts/package-delivery.py` создаёт исходный архив в родительском каталоге. Runtime-секреты, SSH known_hosts, образы Docker и зависимости в него не включаются; известный ключ и строки формата OpenRouter проверяются перед записью. Упакованные файлы также проходят проверку целостности ZIP.
